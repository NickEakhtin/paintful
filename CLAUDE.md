# Project
3D indie game, Godot 4.7, GDScript only.

- The repo root is the Godot project root (`project.godot` is here).
- Development roadmap: `docs/ROADMAP.md`. Each big step gets its own detailed plan before work starts.
- `docs/` has a `.gdignore`, so Godot doesn't scan it.

# Rules
- Godot 4 API only (await, CharacterBody3D, @export). Never Godot 3 syntax.
- Prefer editing .tscn/.gd files directly; keep scenes small and composable.
- Run the game to check for errors (from the repo root):
  /Applications/Godot.app/Contents/MacOS/Godot --path . 2>&1
  Quick headless check that exits by itself:
  /Applications/Godot.app/Contents/MacOS/Godot --headless --path . --quit-after 120 2>&1
- Windows build (preset in `export_presets.cfg`, templates in `~/Library/Application Support/Godot/export_templates/4.7.2.stable/`, only Windows x86_64 and macOS installed):
  /Applications/Godot.app/Contents/MacOS/Godot --headless --path . --export-release "Windows Desktop" build/windows/tattoo.exe 2>&1
  One `.exe` with the pack embedded; `build/` is git-ignored.
- macOS build (universal, ad-hoc signed, not notarized; needs `import_etc2_astc` on):
  /Applications/Godot.app/Contents/MacOS/Godot --headless --path . --export-release "macOS" build/macos/tattoo.app 2>&1
- Commit after each working step.

# Code conventions
- Static typing everywhere: `var speed: float = 5.0`, `func f(x: int) -> void`.
- Files and folders in snake_case. Add `class_name` (PascalCase) only when the class is used as a type elsewhere.
- Feature folders: a scene and its script sit side by side (`main/`, `player/`, `items/`, `world/sandbox/`...).
- Systems talk through the `Events` signal bus, not through absolute node paths into other scenes.
- Autoloads (`autoload/`):
  - `Events` — global signal bus; add signals when a feature needs them (mark each `@warning_ignore("unused_signal")`). Now: `interaction_prompt_changed(text)`, `objective_changed(text)`, `studio_opened`, `studio_closed`, `underground_changed(underground)` (the sky stops lightning below ground).
  - `GameState` — playthrough progress that survives level reloads (`day`, `client_index`, `trophies`).
  - `Transition` — black overlay: `await Transition.change_scene(path)`, `fade_out()`, `fade_in()`, `show_title(text)` (leaves the screen black; call `fade_in()` after), `flash(color)` (instant colour that fades, non-blocking).
  - `Dialogue` — comic-style dialogues, see below.
  - `Display` — the window: starts fullscreen (borderless, desktop resolution); F11, Alt+Enter, Cmd+Ctrl+F toggle it (`set_fullscreen()`), the choice is saved in `user://settings.cfg`; a window is 16:9, 75% of the screen, never under 1280×720. `-- --windowed` / `-- --fullscreen` (user args, after `--`; Godot swallows its own `--windowed`) win over the saved choice. Does nothing headless. Low resolution (default off, F10 switches, saved; `-- --low-resolution` turns it on for a test run): the root window uses `CONTENT_SCALE_MODE_VIEWPORT`, so the whole game renders at the base size (1280×720 widened to the screen, 1280×800 on a MacBook) and is stretched to the window; `RetroPost` takes its pixel size from that render height (2 → 400 rows).
  - `FpsCounter` — FPS in the top left corner over everything (layer 128, updates 4 times a second); F9 hides and shows it.
- Mechanic switches: `data/mechanics.tres` (`Mechanics`, `tattoo/mechanics.gd`), preloaded by `TattooSession` and `DayFlow`: `spirit_tasks` (roulette + tasks; the level skips the spirit's roulette line), `skin_heat`, `ink_supply` (off: endless ink, no gauge, no Q hints), `magnet`, `machine_inertia` (off: needle exactly at the hand, the top still swings), `table_prep`, `table_cleanup`, `skin_press`, `flow`, `flat_brush` (off: the old round brush and smooth trail), `needle_swap` (two needles on the side table), `edge_kick` (inking past the stencil's edge shakes the skin and pushes the machine back), `skin_tension` (the arm takes ink well only where it's pulled taut), `dialogues` (off: `Dialogue.play()` returns at once, every dialogue is skipped and the day goes on). Script defaults are all on; the `.tres` currently switches everything but the press, flow and flat brush off (dialogues too), to work on the bare inking feel. A new mechanic that can get in the way gets a switch here.
- Input actions: `move_forward/back/left/right` (WASD), `interact` (LMB, the colleague's way; E works too), `use` (LMB), `highlight` (RMB), `turn_to_ink` (Q, tattoo session), `hand_up/down/left/right` (WASD) + `hand_wave` (Space) for the left hand in a session, `pause` (Esc). Keys are physical, so they work on any keyboard layout.
- Physics layers: 1 `world`, 2 `player`, 3 `interactable` (bit value 4), 4 `npc`, 5 `player_blocker` (bit value 16: stops the player but not the interaction ray, e.g. the volcano rim, a cabinet you reach into), 6 `prop_physics` (bit value 32: the hanging chains and the glove's body that pushes them; the player walks through and the links swing away).
- Commit the `.uid` files Godot creates next to scripts.

# Building blocks
- `player/player.tscn` (`Player`, group `player`): the colleague's feel: walking at 2.2 m/s with his head bob (`bob_*`, added to the interpolated camera), his mouse sensitivity; running (Shift) and jumping (Space) exist but are off (`can_run`, `can_jump`), as in his game. One held item (`held_item`, `hold()`, `take_item()`) lies across the palm of his glove (`Head/Camera3D/PlayerHand`, `PlayerHand`: follows the camera with inertia, sways with the steps, `tap()` jab on every use, keeps out of walls, pushes the chains; `snap_hand()` after a teleport). `RetroPost` (his low-fi filter, `world/fx/retro_post/`) is in the player scene on layer −1, under every UI layer; a game pixel is a whole number of screen pixels: as big as still fits `min_rows` (480) in the window height, at most `max_pixel_size` (3) — 1080p 540 rows (2 px), the MacBook's 1120 560, 1440p 480, 4K 720, 720p unpixelated; the 3D world renders at one pixel per game pixel (`scaling_3d_scale` = 1 / pixel). On macOS the window has no HiDPI (`window/dpi/allow_hidpi.macos=false`): a Retina screen draws at its point size and macOS doubles it (the MacBook's 3584×2240 window is 1792×1120, about 370 game rows). Full Retina drew 4× the pixels — level 11 → 4.5 ms, session 15 → 8.7 ms a frame on the Radeon Pro 5300M — and heated the laptop until its GPU clocked down (the same frame got twice as slow within a minute); text is a little softer. A click on a free mouse only captures it (in `_input`, before the ray; skipped headless, where there is no mouse to capture).
  Walking runs at the physics rate; the camera is `top_level` and drawn between the last two physics head positions (`_update_camera`, `process_priority` -10), so it doesn't judder when the FPS isn't a multiple of 60. Mouse look applies at once. `HoldPoint` under the camera is only a fallback when there is no glove.
  Block input with `lock_controls(&"reason")` / `unlock_controls(&"reason")`; it stays locked while any reason remains. HUD is inside the player scene.
- `Interactable` (`interaction/interactable.gd`, an Area3D on layer 3 with a CollisionShape3D child): use as is and connect `interacted(player)`, or extend and override `get_prompt()`, `can_interact()`, `interact()`.
  The player's ray (`player/interactor.gd`, 2.5 m) shows `"ЛКМ — <prompt>"` when interaction is possible, the bare prompt when it isn't, nothing for an empty prompt, and draws his outline (`player/outline/`) around a usable target: the Interactable's `outline_mesh` meta (or a MeshInstance3D parent) as a silhouette, `outline_contour` as a ready mesh, otherwise a frame on its shape (`outline_front_sign`); `outline_suppress` hides it; the colour comes from the first node up with `interaction_outline_color()`. Items and clients set `outline_mesh` themselves.
- `items/item.tscn` (`Item`): set `item_id`, `display_name`, `mesh`, `color`, or `model` (+ `model_scale`; set on its bottom) for a real look. Put it under an `ItemSlot` in the editor to start there. No dropping on the floor.
- `items/item_slot.tscn` (`ItemSlot`): `accepts` filters by `item_id` (empty = any); signals `item_placed(item)`, `item_removed(item)`.
- Stairs: visual steps without collision plus an invisible ramp `StaticBody3D` — `CharacterBody3D` doesn't climb steps.
- Scenes: `main/main.tscn` is the start screen and leads to the level; `world/sandbox/sandbox.tscn` is a grey-box test ground (shelf with items, table with slots, stairs, day sign, tattoo chair) with the real player.

## Tattoo session (`tattoo/`)
- Feel goal: as pleasant as cleaning in **PowerWash Simulator**. No timer, no grade, no ink penalties; difficulty comes from spirit tasks (the only ink loss is the Flame task wiping unfinished parts). The one rule outside tasks is skin redness (below): it only catches a needle parked in one place. Any of these can be switched off in `data/mechanics.tres`.
- A 2D screen over the game, not a 3D close-up. `TattooSession` (CanvasLayer 10): add it, then `roll_and_start(stencil)` (roulette first) or `start(stencil, tasks)`; `await session.finished` → `SessionResult` (`tasks`, `passed`, `is_perfect()`). The caller frees it and restores the mouse mode (see `world/sandbox/sandbox.gd`). While it lives the window's own 3D is off (`get_viewport().disable_3d`, restored in `_exit_tree`): the session covers the screen, and the level under it cost about 15 ms a frame on the 3K Retina screen for nothing (session 25 → 15 ms per frame).
  Testing shortcut: F3 in a session fills the stencil and ends it at once (`skip()`; off with `debug_skip_enabled`); the HUD hint mentions it.
  Running `tattoo/tattoo_session.tscn` on its own rolls the roulette and restarts when done — use it for tuning (exports under "Tuning"; set `fixed_tasks` to skip the roulette). Its own `stencil` is now `arm_square` (the forearm); the level and sandbox pass their own stencils.
- Look (exports under "Look"): the machine's 3D renders at the retro filter's game pixel (`TattooMachine.render_divisor`, no MSAA: a quarter or a ninth of the pixels; the filter samples one point per game pixel anyway). The game's retro filter (`world/fx/retro_post/retro_post.gdshader`, same shader) over the skin and the machine: `RetroCopy` + `RetroFilter` after `Machine`, with `HUD` drawn last so its text stays sharp; the game pixel follows the game's rule (`retro_min_rows` 480: 2 screen px on 1080p and the MacBook's 1792×1120, at most `retro_max_pixel` 3); `retro_filter` off hides it.
- Skin and stencil sit in `View/Body` (a full-rect Control) that tasks can push; tasks live in `Body/Modifiers`, so they move with the skin and draw on it. `View/SideTable` + `View/InkCap` sit `table_offset` px to the right; HUD stays put.
- Skin surfaces (`tattoo/surfaces/`, plan: `docs/plan_arm_surface.md`): `SkinSurface` (a Control in `View/Body`) is all the session knows about the skin: `to_cell(screen)` (INF off the skin), `project(cell)` → screen x, y + how much ink lands there (0 where hidden/turned away), `cells_within()`, `brush_basis()`, `is_on_skin()`, `update_surface(delta, active)`, `release()`, `set_highlight()`, `hint()`, `supports_tasks()`. `StencilData.surface` picks it (`SURFACE_SCENES` in the session): `&"flat"` = the old panel (`View/Body/Canvas` with `FlatSurface`), `&"arm"` = `ArmSurface`. Spirit tasks and skin redness only run on surfaces that `supports_tasks()` (flat now); the magnet works everywhere, pulling only toward cells that take ink right now.
  - `ArmSurface` (`surfaces/arm/arm_surface.tscn`): a tapered forearm filling the screen top to bottom, in its own orthographic SubViewport (1 unit = 1 px) with a key/fill light and a bokeh background. Skin coordinates: `theta` around the arm (stencil spans ±`wrap_angle`), `v` along it (`stencil_height` px). The mesh is a flat grid whose UV are skin coords; `arm_skin.gdshader` places the vertices. Skin texture: `skin_detail` / `skin_normal` (two seamless 512 px `NoiseTexture2D`s from one cellular `FastNoiseLite`, `distance2_sub`: the fine criss-cross lines of skin, generated at load, no image files) tile every `detail_tile` (160) skin px, darken by `detail_strength` (0.1) and bump by `normal_strength` (0.5; the vertex shader sets `TANGENT`/`BINORMAL` from the same finite differences as `NORMAL`); stretched skin smooths them, ink halves the bump. Costs nothing measurable. The stencil parts + ink are drawn in `InkLayer` (a 2D SubViewport in skin coords) and wrapped on. Ink lands only where the skin faces the camera (`ink_soft_angle`..`ink_max_angle`), so the stencil's sides hide behind the silhouettes.
  - Pulling: WASD (`hand_*`) move the artist's left hand over the screen (`hand_speed`, `hand_acceleration`, placeholder look `left_hand_visual.gd`, resting low left of the arm); Space (`hand_wave`) grips the skin under the palm and the hand drags it along, any way, no farther than `max_drag` (160 px) from where it took it, until Space is pressed again (a toggle, not a hold). The skin slides over the arm: `ArmShape.slide()` moves every skin point (theta, v) by `drag` (arc px at `radius`, px along the arm) times a gaussian of its distance from the grip (`drag_radius` 200, kept over 1.2 × `max_drag` so it stays invertible: `unslide()` by 24 fixed-point rounds, a few thousandths of a cell off at a full drag), then places it on the arm; `screen_to_skin()` unslides. Skin coordinates stay on the skin, so the stencil and ink stretch with it, and skin slid in from behind a silhouette faces the camera and takes ink (that's how the sides get inked now). Let go (Space again) → it slides back (`drag_return_rate`). `arm_skin.gdshader` repeats `slide()` (uniforms `drag_from`, `drag`, `drag_radius`) — change both together. A grip at least `flap_grip_angle` (40°) round the arm takes the side instead (`_grip_flap`): `_lift_flap()` drives `ArmShape`'s taut flap (`SkinPull` fields set directly: `side` from the grip, `amount` = how far the hand went outward / `max_pull` (160), `angle` from how far it went up or down, `grip_v` = the grip's row), so pulling a side outward lifts the skin off the arm into a flat flap facing the camera — the stencil's side comes into view on every row with clean skin beyond it, and the front isn't squeezed (a slide toward the front made a crease there; the user didn't want it). A side grip moved inward or up and down slides the skin as a front grip does (`_slide_side_grip()`: the inward part of the hand's way and the up-down part the flap's tilt doesn't use, measured on the bare arm from the grip; flap and slide work together), so a side grip never does nothing. Within `side_grab_margin` (70 px) past the silhouette, on the background, Space still takes the side of the skin at the silhouette of that row (`_side_grab()`, a flap grip). Let go and the flap slides back (`SkinPull.update()` with no keys). Sounds `skin_stretch` on gripping, `skin_release` on letting go of a big drag. RMB ping also lights the silhouette on a side that still hides unfinished stencil. ## Spirit tasks (`modifiers/`) and roulette (`ui/roulette/`)
- A task = `ModifierData` (`data/modifiers/*.tres`: name, spirit line, colour, scene) + a scene whose root extends `TattooModifier`.

- Stencils (`StencilData`) are lists of `StencilPart` (name + texture) plus `surface` and `grid_size`. One PNG per part, all the same size, opaque pixels = area to fill; flat ones 2048 px per part (4096 for big ones), imported lossless with mipmaps, so they stay sharp on 4K; arm ones at their layout size for now (the arm's `InkLayer` is as big as they are). Placeholders: `data/stencils/` (square, sigil, eye, moon, and for the arm, 880×700 = the unwrapped skin ±120°: `arm_square`, a plain filled 480 px square whose sides go round the curve to ±65° and need a small pull — the one in use now; `arm_band`, seal in front, wings behind the silhouettes, a diagonal ribbon), generated by `tools/generate_placeholder_stencil.gd`. An arm stencil must stay within reach of a full pull (about ±110°).

## Testing
- To test a flow headless, put a temporary scene in `_test/` (git-ignored) that drives it with `Input.action_press` / `Input.parse_input_event`, run it with `--headless --path . res://_test/<scene>.tscn`, then delete it.
  Pure-logic tests can be a `extends SceneTree` script run with `--headless --path . --script res://_test/<file>.gd`.
- A test that changes the current scene must run from a node added to the root, or it is freed with the old scene.
- Headless windows are tiny: mouse events are in window pixels, so map positions with `get_tree().root.get_final_transform() * viewport_pos`.
- `ImageTexture.get_image()` returns nothing useful headless; check the source `Image` instead.
- To see a screen, run a temporary scene windowed (no `--headless`; the game starts fullscreen, so pass `-- --windowed` to size the window yourself; set `get_window().always_on_top = true`, since macOS doesn't draw a covered window and frame-driven things like the ink look then stall) that saves `get_viewport().get_texture().get_image()` to a PNG in the scratchpad, then read the PNG.

# Game concept
First-person game. The player is a tattoo artist with esoteric leanings: believes in spirits, does occult tattoos.
At the start a dark spirit contacts them: it must be freed, and for that the artist has to carry out its tasks every day.
- **The spirit lives inside the tattoo machine.** The machine is its vessel: it speaks to the artist through it and works through it in every session (the roulette tasks, the spirit-purple glowing needle, the flame on the machine). Keep this in mind for every new spirit line, task and effect.

## Locations
- **Tattoo studio**: small; reception desk, entrance door with an OPEN/CLOSED sign, session chair, workstation with supplies.
- **Basement**: altar to the spirit, spots for candles and other ritual props.

- `characters/umbrella_walker/`: the colleague's passer-by with an umbrella, four frames with normal maps, walking back and forth on the street.

## Art direction
- Characters and animations will be flat 2D sprites in a 3D world (billboards). The user will provide the art later.
- Until then use simple 3D placeholder figures (capsules, CSG/primitive meshes). Build character scenes so the visual can be swapped for a sprite without touching logic.
- Spirit and dialogue text are shown comic-style (speech bubbles / text panels), no voice acting.

## Core mechanic 1: tattooing
- Very casual, modeled directly on **PowerWash Simulator**: move the tattoo machine over the skin, hold to ink, fill the stencil; progress fills by area.
- At the start of every session the spirit spins a **roulette** that gives a combination of tasks (modifiers) that make the session harder. Examples:
  - *Childhood trauma* (client is afraid of spiders): spiders run across the skin, the player must hit them.
  - *Flame*: a flame burns on the machine; moving too fast or too sharply blows it out and the unfinished ink is gone.
- Start with just a couple of modifiers; the system must make adding new ones easy.
- A perfect session makes the client's eyes glow: the spirit says (in text) this client is ready for the ritual.

## Core mechanic 2: the ritual
- After three clients the day ends and night begins. In the basement the player sacrifices one of the clients to the spirit.
- Demo: the chosen client is always the 3rd one. The player leads them to the basement, prepares the ritual (candles and other small tasks), then kills them brutally. Then the next day starts.

## Day loop
1. Day starts → dialogue with the spirit.
2. Go out into the studio, press OPEN.
3. Client arrives → dialogue with the client → roulette gives the spirit's tasks.
4. Prepare the workstation: tiny fetch quest for a few items (needle, ink, ...).
5. Tell the client the station is ready → switch to tattoo mode → tattoo while following the roulette tasks.
6. Client leaves → clean up the workstation (one interaction).
7. Next client is already waiting at reception → repeat from step 3, three clients in total.
8. After the 3rd client the spirit hypnotizes them so they can't leave.
9. Player closes the studio, goes to the basement and prepares the ritual site.
10. Player returns to the client; player, client and spirit end up in the basement and perform the ritual.
11. Black screen with "Day N" → next day.
