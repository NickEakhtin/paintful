# Project
3D indie game, Godot 4.7, GDScript only.

- The repo root is the Godot project root (`project.godot` is here).
- Development roadmap: `docs/ROADMAP.md`. Each big step gets its own detailed plan before work starts.
- `docs/` has a `.gdignore`, so Godot doesn't scan it.

# Rules
- Godot 4 API only (await, CharacterBody3D, @export). Never Godot 3 syntax.
- Prefer editing .tscn/.gd files directly; keep scenes small and composable.
- Run the game to check for errors (from the repo root):
  /Applications/Godot.app/Contents/MacOS/Godot --path . 2>&1
  Quick headless check that exits by itself:
  /Applications/Godot.app/Contents/MacOS/Godot --headless --path . --quit-after 120 2>&1
- Windows build (preset in `export_presets.cfg`, templates in `~/Library/Application Support/Godot/export_templates/4.7.2.stable/`, only Windows x86_64 and macOS installed):
  /Applications/Godot.app/Contents/MacOS/Godot --headless --path . --export-release "Windows Desktop" build/windows/tattoo.exe 2>&1
  One `.exe` with the pack embedded; `build/` is git-ignored.
- macOS build (universal, ad-hoc signed, not notarized; needs `import_etc2_astc` on):
  /Applications/Godot.app/Contents/MacOS/Godot --headless --path . --export-release "macOS" build/macos/tattoo.app 2>&1
- Commit after each working step.

# Code conventions
- Static typing everywhere: `var speed: float = 5.0`, `func f(x: int) -> void`.
- Files and folders in snake_case. Add `class_name` (PascalCase) only when the class is used as a type elsewhere.
- Feature folders: a scene and its script sit side by side (`main/`, `player/`, `items/`, `world/sandbox/`...).
- Systems talk through the `Events` signal bus, not through absolute node paths into other scenes.
- Autoloads (`autoload/`):
  - `Events` — global signal bus; add signals when a feature needs them (mark each `@warning_ignore("unused_signal")`). Now: `interaction_prompt_changed(text)`, `objective_changed(text)`, `studio_opened`, `studio_closed`, `underground_changed(underground)` (the sky stops lightning below ground).
  - `GameState` — playthrough progress that survives level reloads (`day`, `client_index`, `trophies`).
  - `Transition` — black overlay: `await Transition.change_scene(path)`, `fade_out()`, `fade_in()`, `show_title(text)` (leaves the screen black; call `fade_in()` after), `flash(color)` (instant colour that fades, non-blocking).
  - `Dialogue` — comic-style dialogues, see below.
- Mechanic switches: `data/mechanics.tres` (`Mechanics`, `tattoo/mechanics.gd`), preloaded by `TattooSession` and `DayFlow`: `spirit_tasks` (roulette + tasks; the level skips the spirit's roulette line), `skin_heat`, `ink_supply` (off: endless ink, no gauge, no Q hints), `magnet`, `machine_inertia` (off: needle exactly at the hand, the top still swings), `table_prep`, `table_cleanup`, `skin_press`, `flow`. Script defaults are all on; the `.tres` currently switches everything but the press and flow off, to work on the bare inking feel. A new mechanic that can get in the way gets a switch here.
- Input actions: `move_forward/back/left/right` (WASD), `interact` (LMB, the colleague's way; E works too), `use` (LMB), `highlight` (RMB), `turn_to_ink` (Q, tattoo session), `hand_up/down/left/right` (WASD) + `hand_wave` (Space) for the left hand in a session, `pause` (Esc). Keys are physical, so they work on any keyboard layout.
- Physics layers: 1 `world`, 2 `player`, 3 `interactable` (bit value 4), 4 `npc`, 5 `player_blocker` (bit value 16: stops the player but not the interaction ray, e.g. the volcano rim, a cabinet you reach into), 6 `prop_physics` (bit value 32: the hanging chains and the glove's body that pushes them; the player walks through and the links swing away).
- Commit the `.uid` files Godot creates next to scripts.

# Building blocks
- `player/player.tscn` (`Player`, group `player`): the colleague's feel: walking at 2.2 m/s with his head bob (`bob_*`, added to the interpolated camera), his mouse sensitivity; running (Shift) and jumping (Space) exist but are off (`can_run`, `can_jump`), as in his game. One held item (`held_item`, `hold()`, `take_item()`) lies across the palm of his glove (`Head/Camera3D/PlayerHand`, `PlayerHand`: follows the camera with inertia, sways with the steps, `tap()` jab on every use, keeps out of walls, pushes the chains; `snap_hand()` after a teleport). `RetroPost` (his low-fi filter, `world/fx/retro_post/`) is in the player scene on layer −1, under every UI layer; a game pixel is 1/320 of the window height. A click on a free mouse only captures it (in `_input`, before the ray; skipped headless, where there is no mouse to capture).
  Walking runs at the physics rate; the camera is `top_level` and drawn between the last two physics head positions (`_update_camera`, `process_priority` -10), so it doesn't judder when the FPS isn't a multiple of 60. Mouse look applies at once. `HoldPoint` under the camera is only a fallback when there is no glove.
  Block input with `lock_controls(&"reason")` / `unlock_controls(&"reason")`; it stays locked while any reason remains. HUD is inside the player scene.
- `Interactable` (`interaction/interactable.gd`, an Area3D on layer 3 with a CollisionShape3D child): use as is and connect `interacted(player)`, or extend and override `get_prompt()`, `can_interact()`, `interact()`.
  The player's ray (`player/interactor.gd`, 2.5 m) shows `"ЛКМ — <prompt>"` when interaction is possible, the bare prompt when it isn't, nothing for an empty prompt, and draws his outline (`player/outline/`) around a usable target: the Interactable's `outline_mesh` meta (or a MeshInstance3D parent) as a silhouette, `outline_contour` as a ready mesh, otherwise a frame on its shape (`outline_front_sign`); `outline_suppress` hides it; the colour comes from the first node up with `interaction_outline_color()`. Items and clients set `outline_mesh` themselves.
- `items/item.tscn` (`Item`): set `item_id`, `display_name`, `mesh`, `color`, or `model` (+ `model_scale`; set on its bottom) for a real look. Put it under an `ItemSlot` in the editor to start there. No dropping on the floor.
- `items/item_slot.tscn` (`ItemSlot`): `accepts` filters by `item_id` (empty = any); signals `item_placed(item)`, `item_removed(item)`.
- Stairs: visual steps without collision plus an invisible ramp `StaticBody3D` — `CharacterBody3D` doesn't climb steps.
- Scenes: `main/main.tscn` is the start screen and leads to the level; `world/sandbox/sandbox.tscn` is a test ground (shelf with items, table with slots, stairs, day sign, tattoo chair).

## Tattoo session (`tattoo/`)
- Feel goal: as pleasant as cleaning in **PowerWash Simulator**. No timer, no grade, no ink penalties; difficulty comes from spirit tasks (the only ink loss is the Flame task wiping unfinished parts). The one rule outside tasks is skin redness (below): it only catches a needle parked in one place. Any of these can be switched off in `data/mechanics.tres`.
- A 2D screen over the game, not a 3D close-up. `TattooSession` (CanvasLayer 10): add it, then `roll_and_start(stencil)` (roulette first) or `start(stencil, tasks)`; `await session.finished` → `SessionResult` (`tasks`, `passed`, `is_perfect()`). The caller frees it and restores the mouse mode (see `world/sandbox/sandbox.gd`).
  Testing shortcut: F3 in a session fills the stencil and ends it at once (`skip()`; off with `debug_skip_enabled`); the HUD hint mentions it.
  Running `tattoo/tattoo_session.tscn` on its own rolls the roulette and restarts when done — use it for tuning (exports under "Tuning"; set `fixed_tasks` to skip the roulette).
- Skin and stencil sit in `View/Body` (a full-rect Control) that tasks can push; tasks live in `Body/Modifiers`, so they move with the skin and draw on it. `View/SideTable` + `View/InkCap` sit `table_offset` px to the right; HUD stays put.
- `InkCanvas`: pure logic on a 256×256 coverage grid. Ink only lands on stencil cells and builds up over time under the needle; a part auto-completes at 97% (`part_completed`). `find_unfilled_near()` feeds the magnet; `clear()` wipes everything. `blocked` (ellipses in cells, refilled by the session every frame from the tasks' `ink_blocks()`) keeps ink and the magnet out; `is_stencil(cell)`.
- Drawing: each part is a TextureRect with `stencil_ink.gdshader` — crisp edges from the full-res part texture, soft fill from the coverage texture; uniforms `done`, `flash`, `highlight`.
  Wet ink: `InkCanvas` stamps every stencil cell under the needle (already full ones too, so fresh ink lies over old as a glossy layer) with its clock `time` (`inked_at_texture`, half floats); the session advances the clock every frame (even after the end) and feeds it to the shader as `now`. Ink younger than `ink_dry_time` (6 s) is deep black and glossy (pin highlight + a reflected window, bent by a bead at the ink's edges and a slow ripple), then dries to grainy grey-black matte. Wet ink counts as higher than dry (`wet_height`), so a fresh stroke over old ink gets a glossy rim.
- Machine look: the user's 3D model (`art/models/tattoo_machine/`, Nomad Sculpt OBJ, long clip cord stripped on import) rendered in a full-screen perspective SubViewport inside `tattoo/tattoo_machine.tscn` (camera looking down at the skin plane z = 0); every frame the model is placed so its needle tip (`NEEDLE_TIP`) touches the plane under `needle`, so it's seen from different angles across the screen. Right-handed hold: `angle_at_left` (60°) at the left edge down to `angle_at_right` (30°) at the right; never steeper, or the body hides the tip. In the session the needle surface uses a no-depth-test, spirit-purple glowing material so the tip always shows over the body. Weight: setting `machine.needle` sets where the hand wants it, reading it gives where the needle really is — it follows on a spring (`follow_frequency`, `follow_damping`; jumps over `snap_distance` teleport; stepped at most `MAX_STEP` = 1/120 s at a time, since the stiff spring blows up when stepped once per frame below ~35 fps), and the top swings behind the motion on its own spring (`swing_*`, `lean_per_speed`). `tattoo_machine.tscn` in `art/` holds the per-part materials and is also a prop on the studio workstation.
- Needle: `TattooMachine` only reports the mouse (`pointer`) and draws itself at `needle`. `TattooSession._update_needle()` is the one place that turns pointer into needle (magnet pull toward unfilled stencil, then smoothing) — spirit tasks (step 3) add their offsets there.
- Ink supply: the machine holds `ink_capacity` (filled-cell units; `stamp()`/`stroke()` return ink laid down). When dry it still buzzes but lays nothing; the gauge beside the machine turns orange when low and red when empty, the ink cap pulses, the HUD says to turn to it. Each LMB click on the cap adds 1/`refill_clicks` of a full tank (3 clicks from empty) and makes the ink wobble (`InkCap.dip()`).
- The ink cap stands on a side table off screen to the right. Q (`turn_to_ink`) swings the whole `View` (skin + table) left by `table_offset` in `turn_time` with a horizontal smear (`motion_blur.gdshader`); Q again swings back. No screen-edge swings (the user disliked turning with the mouse). Never move or warp the machine/mouse on a swing — the user feels any jump as losing control; it always stays under the mouse. The cap is `tattoo/ink_cap.tscn` (`InkCap`): a small 3D cup with ink inside rendered through a SubViewport. LMB must be released once after the swing back before it inks again.
- Skin redness (every session, exports under "Skin"; off with `Mechanics.skin_heat`): `SkinHeat` (`tattoo/skin_heat.gd`) is pure logic on a coarse grid (`heat_cell` 8 px) over the whole `Skin` panel. The working needle heats a soft circle (`heat_radius`) by time spent over it (`heat_rate`), ink or no ink, dry machine included, stencil or bare skin, but only on the rounded skin; cells left alone for `cool_delay` cool at `cool_rate`. `View/Body/Redness` (`skin_redness.gdshader`, between the stencil and the task layer) blurs it into blotches: pink from `pink_from` (~1 s parked), red at `warn_heat` (~2 s: hiss, the skin flinches, HUD line, heartbeat; the spot throbs on the beat), urgent at `danger_heat` (faster heartbeat, blinking line), and at `fail_heat` (~4 s) the skin gives out: cry, red flash, the spirit says one of `overheat_lines` (`data/dialogues/spirit_overheat_*.tres`, shuffled bag), fade, and the session starts over — all ink gone, full tank, cool skin, view back on the client, the same tasks re-instantiated (no new roulette). `finished` still fires only when the tattoo is done, so callers don't see restarts.
- Skin under the needle (exports under "Feel"; off with `Mechanics.skin_press`): `View/Body/Press` (`skin_press.gdshader`, after `Redness`, before `Modifiers`, with a `PressCopy` BackBufferCopy before it) reads the screen and, while the machine works, pulls the picture toward the tip (`press_radius`, `press_depth`), shades the dent from the lamp, adds a pink halo (`press_tint`) and shakes the skin picture by `skin_buzz` px. Look only; hidden during a swing (`MotionBlur` has its own `BlurCopy`).
- Flow (exports under "Flow"; off with `Mechanics.flow`): `InkFlow` (`tattoo/ink_flow.gd`, pure logic) builds over `flow_build_time` while the needle inks over the stencil (ink in the tank) and moves faster than `flow_min_speed`, holds while it stands, and after `flow_grace` fades over `flow_fade_time` once the stroke breaks; pressing again resumes from the current level. `strength()` widens the brush (`flow_brush_bonus`) and sets `TattooMachine.flow`: higher, louder hum (`flow_pitch`, `flow_volume_db`), faster spray and a breathing spirit-purple `Glow` under the machine sprite. Nothing on the HUD; cleared on overheat and at the end.
- Feedback: per-part white flash + ding rising a whole tone per completed part, HUD flash label, machine hum and ink spray while inking, RMB "ping" lights up what's left and fades.
- Placeholder sounds in `placeholders/sounds/`, synthesized by `tools/generate_placeholder_sounds.gd` (writes only missing files; the hum and whisper loop via their `.import` setting).
- The session ignores input and stops painting while `Transition.is_busy`, so nothing (F3 included) fires before the caller awaits `finished`.

## Spirit tasks (`modifiers/`) and roulette (`ui/roulette/`)
- A task = `ModifierData` (`data/modifiers/*.tres`: name, spirit line, colour, scene) + a scene whose root extends `TattooModifier`.
  Override `needle_offset()`, `skin_offset()`, `machine_weight()`, `ink_blocks()` (viewport-pixel rects whose inscribed ellipses take no ink), `can_ink()`, `status_text()`, `is_passed()`, `stop()` (call `super()`). `draw_order` (export on the task's root) stacks tasks in the task layer: lower draws under (Chatterbox −2). `session` and `data` are set before `_ready`.
  Session API for tasks: `needle_position()`, `pointer_position()`, `needle_velocity()` (the spring needle, zero after a teleport), `machine_top_position()` (screen point of `TattooMachine.TOP`), `is_turning()`, `is_working()` (machine inking right now, dry included), `stencil_rect()` (stencil in task-layer coordinates), `wipe_unfinished(color)`, `red_spot()` (hottest red skin spot in viewport pixels, `Vector2.INF` while none), `skin`.
  `machine_weight()` from all tasks is summed into `TattooMachine.weight`: both machine springs run at frequency / sqrt(1 + weight), so it follows slower and swings more.
  Adding a task: new folder + `.tres`, then add it to `task_pool` in `tattoo/tattoo_session.tscn`. No session code changes.
- The roulette never repeats a task and has no empty reels: every session gets three different tasks (fewer only if the pool is smaller).
  `ModifierData.excludes` lists task `id`s that never come up in the same session (checked both ways; Moths excludes Flame). A task with an empty `spirit_line` is silent on the roulette.
- Pool now: Spiders, Flame, Moths, Chatterbox and Observers (Fear and Pain were removed).
- Spiders: one every `spawn_interval` (5 s, ±30%; first after 2.5 s); click (needle or mouse within `hit_radius`) to squash; more than `allowed_escapes` escapes fails.
- Flame: a flame burns on the machine top (`Fire` node, `top_level`, `z_index` over the machine, `flame.gdshader`). Needle speed over `safe_speed` drains it, at `blowout_speed` it goes out at once. Out: hiss + smoke, `wipe_unfinished()` (done parts stay), `can_ink()` false until the needle stays under `still_speed` for `relight_time`. More than `allowed_outs` outs fails. The look follows the current speed (`_gust`, from `react_from` × `safe_speed`): the flame shrinks, tears, flickers faster and reddens before any flame is lost, so the player sees "too fast" early. A 500 px move takes about half the flame in 0.35 s and blows it out in 0.25 s.
- Moths: tiny pale-blue fairies (`Moth`, drawn in `_draw`, hang by their hands under the machine body) fly in from the screen edge, first after `first_spawn` (3 s), then every `spawn_interval` (6 s, ±30%), none during a swing. Each perched one adds `weight_per_moth` to the machine and pulls the needle down by `sag_per_moth`; at most `max_moths` (6) perch, the rest circle the top. Shaking the mouse knocks them off: `ShakeDetector` counts fast (`shake_min_speed`), long (`shake_min_stroke`), straight swings that turn back sharply — stencil strokes and fast curves don't count; each one takes `shake_grip_loss` of every fairy's grip, which recovers at `grip_recover`. About three quick swings clear the machine. Can't be failed; no spirit line.
- Left hand (`tattoo/left_hand.tscn`, `LeftHand`): for tasks that need the artist's free hand. A task instances it and adds it as its own child (it's `top_level`, so it stays in screen pixels through swings), sets `bounds`, calls `slide_in(from, to)`, listens to `waved`, reads `palm()`; `leave()` slides it off and frees it. WASD move it with inertia (`speed`, `acceleration`), Space waves (swish; `waved` fires at once). Look in `Visual` (placeholder `_draw`: just the back of a left hand floating in the air, no arm). Ignores input while `Transition.is_busy`.
- Chatterbox (`modifiers/chatter/`, id `chatter`): the spirit loosens the client's tongue. A `ChatBubble` with a silly question (`phrases` on `chatter.tscn`, shuffled bag) pops up over the centre of a free stencil quarter (corner 0–3) after `first_delay` (7 s), then every `interval_min`–`interval_max` (8.5–16.5 s); four at most, it waits for a free corner. The left hand waves it away: Space pops every bubble whose rect, grown by `hit_margin`, holds the palm; a bubble under the palm glows yellow. A hit plays pop + "mm-hm" and floats a cream `reply.tscn` ("Угу.", from `replies`) by the fingertips. `draw_order` −2 keeps it at the bottom of the task layer so spiders and fairies stay visible over bubbles. A bubble over red skin gets a red rim (`alarmed`), so redness is never hidden. Can't be failed.
- Observers (`modifiers/observers/`, id `observers`, `draw_order` −1: over Chatterbox bubbles, under spiders and fairies): the spirit watches through the client's skin. `eye_count` (3) `Eye`s sit on random stencil spots inside the skin, `min_spacing` apart, for the whole session. An eye surfaces shut, first opens after `first_open_min`–`max`, then cycles: open `open_min`–`max` (4–7 s) → shut `closed_min`–`max` (3–5 s) → lid trembles `warn_time` (0.7 s) → opens (`blink_time` lids). While open (opening/closing included) `ink_blocks()` keeps ink and the magnet out of its ellipse; ink under a shut eye shows and fills as usual. Pupils follow the needle within `look_range`, glance around beyond it. An open eye over red skin turns bloodshot (`alarmed`). Poke: `is_working()` needle inside an open eye for `poke_time` (0.1 s, so a quick spider click doesn't count), not during the first `open_grace` (0.3 s) after it starts opening; staying in counts again every `hit_cooldown` (1 s), leaving resets. A poke: the eye winces (`flinch`), the client flinches (`skin_offset()`), squelch. More than `allowed_hits` (2) fails; no HUD counter. Sounds: open/close/twitch per `Eye.state_changed`. `stop()` shuts them for good. Look: `Visual` (`eye_visual.gd`, `_draw` placeholder, reads the eye's `openness`, `presence`, `tremble`, `gaze`, `alarmed`, `flinch`).
- `Roulette`: three reels, each a different task; `await roulette.spin(pool)` returns the tasks after the player clicks.
- Stencils (`StencilData`) are lists of `StencilPart` (name + texture). One PNG per part, all the same size, opaque pixels = area to fill. Placeholders: `data/stencils/` (square, sigil, eye, moon), generated by `tools/generate_placeholder_stencil.gd`.

## Testing
- To test a flow headless, put a temporary scene in `_test/` (git-ignored) that drives it with `Input.action_press` / `Input.parse_input_event`, run it with `--headless --path . res://_test/<scene>.tscn`, then delete it.
  Pure-logic tests can be a `extends SceneTree` script run with `--headless --path . --script res://_test/<file>.gd`.
- A test that changes the current scene must run from a node added to the root, or it is freed with the old scene.
- Headless windows are tiny: mouse events are in window pixels, so map positions with `get_tree().root.get_final_transform() * viewport_pos`.
- `ImageTexture.get_image()` returns nothing useful headless; check the source `Image` instead.
- To see a screen, run a temporary scene windowed (no `--headless`) that saves `get_viewport().get_texture().get_image()` to a PNG in the scratchpad, then read the PNG.

# Game concept
First-person game. The player is a tattoo artist with esoteric leanings: believes in spirits, does occult tattoos.
At the start a dark spirit contacts them: it must be freed, and for that the artist has to carry out its tasks every day.
- **The spirit lives inside the tattoo machine.** The machine is its vessel: it speaks to the artist through it and works through it in every session (the roulette tasks, the spirit-purple glowing needle, the flame on the machine). Keep this in mind for every new spirit line, task and effect.

## Locations
- **Tattoo studio**: small; reception desk, entrance door with an OPEN/CLOSED sign, session chair, workstation with supplies.
- **Basement**: altar to the spirit, spots for candles and other ritual props.

## Art direction
- Characters and animations will be flat 2D sprites in a 3D world (billboards). The user will provide the art later.
- Until then use simple 3D placeholder figures (capsules, CSG/primitive meshes). Build character scenes so the visual can be swapped for a sprite without touching logic.
- Spirit and dialogue text are shown comic-style (speech bubbles / text panels), no voice acting.

## Core mechanic 1: tattooing
- Very casual, modeled directly on **PowerWash Simulator**: move the tattoo machine over the skin, hold to ink, fill the stencil; progress fills by area.
- At the start of every session the spirit spins a **roulette** that gives a combination of tasks (modifiers) that make the session harder. Examples:
  - *Childhood trauma* (client is afraid of spiders): spiders run across the skin, the player must hit them.
  - *Flame*: a flame burns on the machine; moving too fast or too sharply blows it out and the unfinished ink is gone.
- Start with just a couple of modifiers; the system must make adding new ones easy.
- A perfect session makes the client's eyes glow: the spirit says (in text) this client is ready for the ritual.

## Core mechanic 2: the ritual
- After three clients the day ends and night begins. In the basement the player sacrifices one of the clients to the spirit.
- Demo: the chosen client is always the 3rd one. The player leads them to the basement, prepares the ritual (candles and other small tasks), then kills them brutally. Then the next day starts.

## Day loop
1. Day starts → dialogue with the spirit.
2. Go out into the studio, press OPEN.
3. Client arrives → dialogue with the client → roulette gives the spirit's tasks.
4. Prepare the workstation: tiny fetch quest for a few items (needle, ink, ...).
5. Tell the client the station is ready → switch to tattoo mode → tattoo while following the roulette tasks.
6. Client leaves → clean up the workstation (one interaction).
7. Next client is already waiting at reception → repeat from step 3, three clients in total.
8. After the 3rd client the spirit hypnotizes them so they can't leave.
9. Player closes the studio, goes to the basement and prepares the ritual site.
10. Player returns to the client; player, client and spirit end up in the basement and perform the ritual.
11. Black screen with "Day N" → next day.
